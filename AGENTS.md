# Project collaboration preferences

## Visual understanding

The user explicitly prefers human-centered visual communication across this project. Make interfaces, mockups and explanations easy to understand at a glance through meaningful icons, labelled diagrams, clear grouping, visual hierarchy, readable typography, status text and obvious next actions. Use visual aids when they clarify the subject; keep simple answers concise rather than adding unnecessary diagrams.

For product screens, help users quickly understand where they are, what the current state means and what to do next. Favor understandable question → answer → evidence flows over dense text or unexplained technical graphs. Preserve a polished, creative design; visual simplicity should not become a generic repetitive card layout. Never substitute decorative or fabricated metrics for meaningful information.

## Scope and deliverables

Do only the work the user requests. When the user requests a separate documentation file, create it separately without merging into or changing existing documents unless asked. Maintain continuity with the project's saved development setup and design specifications, subject to the user's latest instructions.

This file preserves preferences for this repository; it does not establish account-wide memory.
